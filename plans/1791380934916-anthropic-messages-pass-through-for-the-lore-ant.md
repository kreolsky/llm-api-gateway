# Anthropic Messages pass-through for the Lore anthropic route

## Decisions

- Goal, agreed with Lore: Lore's harness (pi-ai, `api: anthropic-messages`, baseURL = the router root WITHOUT `/v1`, the router's key) sends native Messages requests to the router; the router checks key and model access, rewrites only `model`, forwards body and stream unchanged to an Anthropic-protocol upstream, and records usage including cache writes. `/v1/models` tells Lore per model which protocol to use (`api`) and the pi-ai `compat` flags. Lore's catalog, model access, effort levels and backend do not change; keys, access and accounting stay in the router.
- Current behaviour to change: there is one provider type, `PROVIDER_TYPES = ("openai",)` (`src/core/config_schema.py:107`), one factory arm (`src/providers/__init__.py:20`), no `/v1/messages` route (`src/api/main.py:205` is the chat route), auth reads only Bearer (`src/core/auth.py:35`), and cost ignores cache writes (`src/core/usage_db/writer.py:238`).
- Provider type `anthropic` (add to `PROVIDER_TYPES`; the factory becomes a `{type: class}` dict). A provider speaks exactly one protocol, so a model's protocol is its provider's type: `openai` -> `/v1/chat/completions`, `anthropic` -> `/v1/messages`. A dual-protocol vendor gets two provider entries. Test entry: `deepseek-anthropic: {type: anthropic, base_url: https://api.deepseek.com/anthropic, api_key_env: DEEPSEEK_API_KEY}` and model `deepseek-a/flash: {provider: deepseek-anthropic, provider_model_name: deepseek-v4-flash}`. A real Anthropic entry later: `base_url: https://api.anthropic.com`.
- `AnthropicProvider(Provider)` in new `src/providers/anthropic.py` (`SYSTEM: anthropic-provider`): static headers = `headers:` + `Content-Type: application/json` + `x-api-key: <env key>` + `anthropic-version: 2023-06-01`, no `Authorization`. Methods `messages` (via `_request`, so 429 retry and timeouts match `chat_completions`) and `messages_stream` (via `_stream_request`), both POST `{base_url}/v1/messages` with `body["model"] = provider_model_name`, `models.yaml` `options:` deep-merged (Anthropic-wire for these models, e.g. `thinking`, `output_config`, `cache_control`) with the `stream` guard of `_apply_model_config` (`src/providers/base.py`). `list_models` GETs `{base_url}/v1/models` (Anthropic serves it; DeepSeek 404s into the stale-if-error path).
- `_merge_request_headers` (`src/providers/base.py:220`) protects `x-api-key` exactly like `authorization`; `FORBIDDEN_STATIC_HEADERS` (`src/core/header_policy.py:65`) gains `x-api-key`; the class INVARIANT above `Provider` names both credential headers.
- Protocol gate in the one funnel: `_resolve_target` (`src/services/base.py:159`) takes a required keyword `api` (`"openai-completions"` from chat/embeddings/transcription, `"anthropic-messages"` from the new service) and, AFTER `resolve_model` (access before existence stays intact), raises new `ErrorType.WRONG_API` (400, `"Model '{model_id}' is served over {expected_path}"`, `error_code: wrong_api`) when the provider instance's type disagrees. Every endpoint gets it by construction.
- `src/services/messages_service.py` `MessagesService(BaseService)`: `_parse_json_request` + `_resolve_target(api="anthropic-messages")`, NOT `_prepare_dispatch` (`src/services/base.py:203`): the effort policy and dialect translation are OpenAI-wire and must not touch a Messages body; the effort levels in `/v1/models` still come from the `reasoning_effort` block (advertisement only for these models). Client `anthropic-version` and `anthropic-beta` are forwarded on this path even without `identity: passthrough` (protocol, not identity), merged into the one per-request `extra_headers` (same rule as the INVARIANT at `src/services/base.py:170`). Non-stream: `JSONResponse` of the upstream body as-is. Stream: `stats.stream = True`, `open_provider_stream`, `StreamingResponse(process_stream(..., wire=ANTHROPIC_STREAM))`, headers as in `ChatService._stream_response`.
- Auth: `get_api_key` (`src/core/auth.py:35`) takes the client key from `x-api-key` when no Bearer is present (the Anthropic SDK inside pi-ai sends `x-api-key`), every route, same `_find_project` constant-time compare; Bearer wins when both are sent. `x-api-key` is already on the passthrough denylist (`src/core/header_policy.py:22`), so it never goes upstream.
- Usage, one extraction point: `RequestStats` gains `cache_write_tokens` and `set_anthropic_usage(usage)`: `prompt_tokens = input + cache_read + cache_creation`, `cached_tokens = cache_read`, `cache_write_tokens = cache_creation`, `completion_tokens = output`, `total = prompt + completion`. `set_usage` (`src/core/usage_db/writer.py:87`) also reads `prompt_tokens_details.cache_write_tokens` (OpenRouter reports it). New column `cache_write_tokens INTEGER NOT NULL DEFAULT 0` via `_MIGRATIONS` and the INSERT.
- Cost (`_compute_cost_usd`, `src/core/usage_db/writer.py:205`): `(prompt - cached - cache_write) * prompt + cached * input_cache_read + cache_write * input_cache_write + completion * completion`; a missing `input_cache_write` falls back to the prompt rate (same rule and `WHY` as `input_cache_read`). `input_cache_write` joins `PRICING_KEYS` (`src/core/model_capabilities/render.py:13`), so `model_info.yaml` pricing and the OpenRouter normalizer carry it and `/v1/models` renders it. Update the docstring formula and keep the per-token INVARIANT.
- Stream usage: `process_stream` (`src/services/chat_service/stream_processor.py`) gets `wire: StreamWire = OPENAI_STREAM`, a frozen `(capture_usage, record_usage, frame_error)`. `ANTHROPIC_STREAM` captures, byte-gated on `b'"input_tokens"'` / `b'"output_tokens"'`, `message.usage` of `message_start` and the top-level `usage` of `message_delta` (observed on DeepSeek: both carry the full set), merged key by key (later wins), recorded in the existing `finally` via `set_anthropic_usage`. Chunks are still yielded unchanged before any peek; the reasoning remap runs for the OpenAI wire only; the error peek is shared (`{"type":"error","error":{...}}` already matches it). Mid-stream router failure frame: `event: error\ndata: {"type":"error","error":{"type","message"}}\n\n`.
- Error shape on `/v1/messages`: router-made errors are rendered `{"type":"error","error":{"type","message"}}` by the HTTP handler (`src/api/main.py:123`) and the unhandled handler (`src/api/main.py:151`), AFTER the stats enrichment reads the OpenRouter envelope. Status -> type: 400 `invalid_request_error`, 401 `authentication_error`, 403 `permission_error`, 404 `not_found_error`, 413 `request_too_large`, 429 `rate_limit_error`, 503/529 `overloaded_error`, else `api_error`. One converter in new `src/core/error_handling/anthropic.py`, also used by the stream frame.
- `/v1/models`: every model carries `api` (`"openai-completions"` | `"anthropic-messages"`, derived from its provider's type in `ModelService.list_models` and `retrieve_model`, `src/services/model_service.py:163`), and `compat` when set: a new `model_info.yaml` key (`_MODEL_INFO_KEYS`, `src/core/config_schema.py:277`), a mapping of string keys to bool/str/int (e.g. `{forceAdaptiveThinking: true, supportsMidConvoEffort: true}`), anything else warned and dropped (soft, like the other model_info keys); manual layer only, rendered as stored.
- `/v1/capabilities` (Lore reads effort levels from it, not from `/v1/models`): `ModelService.capabilities` (`src/services/model_service.py:176`) already walks every visible model regardless of provider type, and `effort_levels` come from the model's `reasoning_effort` block (`src/services/model_service.py:81`). So an anthropic-type model appears there by construction once it has the block; a test pins it. For these models the block is advertisement only (no gate on `/v1/messages`); its `param` is ignored — say so in a `models.yaml` comment.
- What Lore reads from `/v1/models` and therefore every anthropic-type model needs in `model_info.yaml`: `context_length`, `max_completion_tokens`, `architecture.input_modalities` (Lore otherwise falls back to a 128000 window and no images), `pricing` incl. `input_cache_write`, and `compat` only for real Claude models. The `config/model_info.yaml` header documents this as the anthropic-type checklist, and `compat` joins its schema comment.
- Test config: `deepseek-a/flash` in `models.yaml` with `reasoning_effort: {allowed: [low, high, max]}` (same levels as `deepseek/flash`); in `model_info.yaml` the same `context_length`, `max_completion_tokens`, modalities, `reasoning` and `pricing` as `deepseek/flash`, and NO `compat`: with `supportsMidConvoEffort` pi-ai sends `thinking.block_binding` and mid-conversation `output_config` system messages, which DeepSeek is expected to reject.
- Routes in `src/api/main.py`: `POST /v1/messages`, name `messages`, `check_endpoint_access("/v1/messages")`; `app.state.messages_service` in `lifespan`.
- Size: M — one commit to `dev`; high entanglement (auth, provider base, stream processor, usage writer, error handler, config schema). Full `tests/` twice, `/review`, live drive.

## Risks

- OpenAI-path regression from the header-merge, `_resolve_target` and `process_stream` signature edits. Signal: existing unit suites; the regression drive of `deepseek/flash`.
- `x-api-key` auth on every route. Signal: auth tests with a refused key in `x-api-key`, Bearer precedence.
- Exact-surface `/v1/models` tests break on the new `api` field and the `input_cache_write` pricing key — an intended contract change: update their expected payloads in the same commit and say so in the commit body.
- 1h cache writes are priced at the single `input_cache_write` (5-minute) rate — under-reported 2x vs 1.25x. Signal: none in rows; accepted.
- Verification boundary: the DeepSeek drive proves the chain — pass-through, budget thinking, tools, stream, accounting, access — and NOT the Claude `compat` flags (`forceAdaptiveThinking`, `supportsMidConvoEffort`) nor real cache-write pricing. Those need one live Lore turn on a real Claude model once a key exists (owner: user + Lore).
- pi-ai's Anthropic SDK may send headers the upstream rejects. Signal: 400 in the Lore drive; then narrow the forwarded `anthropic-beta`.

## Not doing

- Translating OpenAI <-> Anthropic (an OpenAI client on an anthropic-type model gets 400 `wrong_api`); Lore's backend direct calls stay on OpenAI-type models.
- `/v1/messages/count_tokens`, Batches, Files; an Anthropic-shape normalizer for the capabilities auto-cache (`compat`, context and pricing for Claude models come from `model_info.yaml`).
- Gating `output_config.effort` with the `reasoning_effort` policy.
- A cache-write column on the `/stat/` dashboard.
- A real Anthropic provider entry: added by the operator once a key exists.
