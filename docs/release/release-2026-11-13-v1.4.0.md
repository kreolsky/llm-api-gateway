# Release v1.4.0 — 2026-11-13

version: v1.4.0 — feat×2.

2 commits (merges excluded) since v1.3.0. The theme is reach: an OpenAI-wire client can
now use Claude-type models for structured extraction, and the router serves reranking.

# What changed for clients

## Chat completions over anthropic-type models (non-streaming)

- `POST /v1/chat/completions` now serves a model whose provider is `type: anthropic` when
  the request is NOT streaming. Before, every such request answered 400 `wrong_api`. A
  client that speaks only the OpenAI wire (Lore's pipeline extractor and image prompt
  refiner) can therefore run on a deployment that has only Claude models.
- The router translates the body to the Messages API and the answer back:
  - `system` / `developer` messages are joined into the top-level `system`;
  - `response_format: {type: json_schema}` becomes `output_config.format`, with a
    `type: [T, "null"]` property rewritten to `anyOf` and `minimum`/`maximum`/length
    bounds stripped;
  - `max_tokens` / `max_completion_tokens` map to `max_tokens`, defaulting to the
    model's `max_completion_tokens` from `model_info.yaml`;
  - `stop` maps to `stop_sequences`;
  - `temperature`, `top_p` and every reasoning field are dropped (current Claude models
    refuse sampling parameters);
  - only `text` blocks reach `choices[0].message.content`; `stop_reason` maps to
    `finish_reason` (`max_tokens` → `length`, `refusal` → `content_filter`).
- A field with no Messages equivalent (`tools`, image parts, `n > 1`, `logprobs`,
  `response_format: json_object`, `tool` messages) is a 400 `invalid_parameter_value`
  naming the field, never a silent drop.
- Usage rows are recorded exactly as on `/v1/messages`, cache read/write split and cost
  included.
- Unchanged: a streaming chat request for such a model, and `/v1/embeddings` /
  `/v1/audio/transcriptions` naming it, still answer 400 `wrong_api`. `/v1/models` keeps
  `api: anthropic-messages` for these models.

## Rerank endpoint

- `POST /v1/rerank` forwards query/documents scoring to an openai-type provider's
  `/rerank` (llama-server `--reranking`, Jina/Cohere shape). It behaves like embeddings:
  model access checked before existence, identity headers, usage recorded, the
  embeddings read timeout.

# Upgrade actions

- `main`: `81a7eac` → this release's SHA (fast-forward).
- Code-only: `requirements.txt` and `Dockerfile` unchanged, so `docker compose restart`
  is enough.
- No new env vars. No usage DB schema changes.
- To let Lore's extractor list a Claude model, add `structured_outputs` to that model's
  `supported_parameters` in the server's `config/model_info.yaml` (hand edit,
  hot-reloaded). Check that the model also carries `max_completion_tokens` there.
- To use rerank, configure a provider pointing at a `/rerank`-serving backend and a model
  on it in `providers.yaml` / `models.yaml`. A key with an `allowed_endpoints` list needs
  `/v1/rerank` added to it.

# Known limitations

- No streaming, tools, images or multi-choice on chat completions for anthropic-type
  models.
- Determinism: `temperature: 0` is dropped, so the same input can extract differently on
  Claude.
- DeepSeek's Anthropic endpoint (`deepseek-anthropic`) accepts `output_config.format`
  but ignores it: it answers with fenced JSON. Do not declare `structured_outputs` on
  its models.
- Not yet driven against a real Claude model; it was driven against `deepseek-a/flash`.
