# Release v1.2.1 — 2026-10-07

version: v1.2.1 — feat×1 ruled internal.

3 commits (merges excluded) since v1.2.0. The theme is the compat contract for the Lore
route: `compat` on anthropic-type models is filtered at load to dsh's offered key set, and
`deepseek-a/flash` is brought in line with production so pi-ai drives it with adaptive
effort instead of budget thinking. Plus documentation (README, deploy skill).

# What changed for clients

## Model capabilities (`/v1/models`)

- `compat` on an anthropic-type model is now filtered at load to the seven allow-listed
  keys (`ANTHROPIC_COMPAT_KEYS` in `src/core/config_schema.py` — exactly dsh's anthropic
  `offer` set): `forceAdaptiveThinking`, `supportsStrictTools`,
  `supportsEagerToolInputStreaming`, `supportsCacheControlOnTools`, `supportsTemperature`,
  `allowEmptySignature`, `supportsLongCacheRetention`. Any other key is warned and dropped;
  a compat whose every key is dropped disappears from the entry. `compat` on non-anthropic
  provider types is unchanged — kept as stored.
- Load-time checklist warnings: an anthropic-type model whose `model_info.yaml` entry lacks
  `context_length` or `max_completion_tokens` gets one warning per missing key (soft, never
  fatal) — the case where pi-ai silently falls back to a 128k window.
- Repo `config/model_info.yaml`: `deepseek-a/flash` aligned with production —
  `context_length 524288`, `max_completion_tokens 131072`, input modalities
  `[text, image]`, no `input_cache_write` (DeepSeek reports `cache_creation_input_tokens: 0`)
  — and gains `compat: {forceAdaptiveThinking: true}`: pi-ai then sends
  `thinking: {type: adaptive}` + `output_config: {effort}` instead of `budget_tokens`
  (measured: DeepSeek honours `output_config.effort`, shows no measurable response to
  `budget_tokens`).

# Upgrade actions

- `main`: `2c0d18e` → this release's SHA (fast-forward).
- Upgrade via `deploy-server`, code-only: `requirements.txt` and `Dockerfile` are
  unchanged, so rsync `src/` + `docker compose restart` is enough — both routers.
- No new env vars. No usage DB schema changes.
- Prod configs (edited by hand on the server; hot-reload, no restart): to turn on adaptive
  effort, add `compat: {forceAdaptiveThinking: true}` to the `deepseek-a/flash` entry of
  the main router's `config/model_info.yaml`. The ext router has no `deepseek-a` models.
- After deploy: `ssh docker "curl -s localhost:8777/health"` →
  `{"status":"ok","version":"v1.2.1"}` (and the same on :8778).

# Known limitations

- Of the advertised effort levels on `deepseek-a/flash` only `max` measurably separates;
  `low` vs `high` was within noise. Accepted — the levels stay as the operator configured
  them.
- dsh drift: when Lore bumps its dsh/pi-ai pin, the allow-list must be re-diffed against
  `ANTHROPIC_COMPAT_GATE` (the `INVARIANT` on `ANTHROPIC_COMPAT_KEYS` names the file); a
  new offered key is dropped with a warning until then.
- DeepSeek may later reject `thinking.type: "adaptive"` (signal: HTTP 400 on every Lore
  turn on the model; fix: remove the compat line from the production config, hot reload).
