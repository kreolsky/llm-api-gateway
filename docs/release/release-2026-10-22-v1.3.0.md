# Release v1.3.0 — 2026-10-22

version: v1.3.0 — chore×1, docs×1; minor by operator ruling (first published image).

2 commits (merges excluded) since v1.2.1. The theme is distribution: the router is now
published as a prebuilt image, so an installation (Lore's public compose first among
them) pulls it instead of building it from a checkout.

# What changed for operators

## Prebuilt image

- Every release tag `vX.Y.Z` publishes `ghcr.io/kreolsky/llm-api-gateway:X.Y.Z` and
  `:stable` (GitHub Actions, `.github/workflows/publish.yml`).
- The image carries no config: `config/` is excluded from the build context. Mount your
  `config/` at `/app/config` and pass provider keys as env vars; without the mount the
  router refuses to start with `Critical config file missing: config/providers.yaml`.
  Keep `/app/data` on a named volume (usage database).
- `/health` of the image reports the tag (`{"status":"ok","version":"v1.3.0"}`): the
  workflow stamps it into `src/VERSION` before the build.
- README → Quick Start → *Prebuilt image* has the `docker run` line.

# Internal (no client-visible change)

- `config/model_info.yaml` comments name what `response_format` / `structured_outputs`
  advertise (Lore's extractor lists only models declaring `structured_outputs`).

# Upgrade actions

- `main`: `0014abd` → this release's SHA (fast-forward).
- Prod routers: nothing to do — they keep the rsync deploy (`deploy-server`), code-only,
  `requirements.txt` and `Dockerfile` unchanged, so `docker compose restart` is enough.
- No new env vars. No `config/*.yaml` key changes. No usage DB schema changes.
- One-time, on the first publish: set the ghcr package `llm-api-gateway` to public in
  GitHub (Packages → Package settings → Change visibility); a new package is private and
  an anonymous `docker pull` is `denied` until then.

# Known limitations

- The image is `linux/amd64` only (the default buildx platform of the runner).
